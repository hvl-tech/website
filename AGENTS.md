# HVLtech website

Website of the Havelland Tech Community (hvltech.de). A friendly local tech community: a dinner every month in a different Havelland town (Tour de Havelland), talk nights and Kids Labs. Home base is Falkensee.

Repo: [github.com/hvltech/website](https://github.com/hvltech/website). Every push to `main` deploys to GitHub Pages (hvltech.de).

## Commands

```bash
npm run dev              # Dev server (add `-- --host <ip>` to reach it from another device)
npm run build            # Production build (runs generate-feeds first)
npm run lint             # ESLint
npm run type-check       # tsc --noEmit
npm run fetch-events     # Refresh src/data/meetup-events.json from Meetup
npm run generate-feeds   # Write public/rss.xml, atom.xml, events.ics
npm run build-map        # Rebuild src/data/havelland-map.json from OpenStreetMap (add `-- --refresh` to refetch)
```

There is no test framework. Don't add test files unless asked. Validation happens in the browser, see below.

## Writing copy

The site speaks for a neighbourly community, not a company. Every text change follows these rules:

- **Friendly and community oriented.** Write like a neighbour inviting someone to dinner. Use "we" and "you" (German: "du"). Welcome every experience level. Light tech humour is fine; the main message is always forming a local community.
- **No em dashes (—).** Don't use spaced en dashes (" – ") as punctuation either. Use a comma, a colon or a new sentence instead. En dashes are only for ranges: `20–50`, `10:00 – 13:00`.
- **Short sentences, plain words.** Prefer two short sentences over one long one.
- **Honest numbers.** Don't oversell. Talk nights have around 20 people, so say "~20".
- **Always bilingual.** Every string lives in both `src/translate/en.ts` and `src/translate/de.ts`, with the same structure. No hard-coded copy in components. Lists (events, FAQ, formats) are arrays read with `returnObjects: true`.

The same tone applies to commit messages, PR descriptions and anything posted on behalf of HVLtech.

## Project structure

```
src/
├── App.tsx                   # Routes. Only /labs still uses the legacy header/footer
├── component/
│   ├── site/SiteLayout.tsx   # Shared sticky header, footer, feed links, PixelIcon, BrandLogo
│   ├── HavellandScene.tsx    # Panorama; canvas water with Kingdom-Two-Crowns-style reflections
│   ├── HavellandMap.tsx      # Pixel map of the district with the Tour de Havelland route
│   ├── PearMascot.tsx        # Waving pixel pear
│   ├── PixelArt.tsx          # Tiny sprites from text grids (FAQ and format illustrations)
│   └── PhotoWall.tsx         # Every image in src/assets/galerie/** shows up automatically
├── pages/                    # HomePage, SpeakersPage, DatenschutzPage (+ page CSS), KidsPage (legacy)
├── styles/site.css           # Design tokens and shared building blocks
├── data/
│   ├── havelland.ts          # Towns, label offsets, tour schedule (monthly, December off)
│   ├── havelland-map.json    # Generated by `npm run build-map`, don't edit by hand
│   └── meetup-events.json    # Generated by `npm run fetch-events`
├── translate/en.ts, de.ts    # All copy. `site.*` is shared, `home.*` is the homepage
└── utils/                    # i18n (browser language, German fallback), eventLinks, useSeo
```

Feeds (`public/rss.xml`, `atom.xml`, `events.ics`) are generated at build time and gitignored. Keep them linked in the header (`<link rel="alternate">`) and visibly on the page.

## Design

- **Tokens** live on `.havel-site` in `src/styles/site.css`: paper `#f8f5e9`, green `#1c7550`, ink `#1f3b33`, muted `#5b6a5b`, line `#d9deca`, accent `#d0643b`.
- **Fonts:** `Press Start 2P` for headings, `VT323` for labels and pixel UI, `DM Mono` for body text.
- **Pixel look:** notched `.pixel-button`, `.pixel-card` with a hard offset shadow, SVG with `shapeRendering="crispEdges"`.
- **New pages** wrap their content in `SiteLayout` and reuse `.page-hero`, `.page-section`, `.pixel-card` and `.chip-list` before adding page CSS.
- **Motion stays subtle.** Only a few things move. Respect `prefers-reduced-motion` and the pause toggle (`.motion-paused`). The opening animation runs on desktop only.
- **Map data** comes from OpenStreetMap. The "© OpenStreetMap contributors" credit must stay visible.

## Validate every change on mobile, tablet and desktop

A change isn't done until it has been looked at in a real browser at all three sizes, including the interactive parts. Use [playwright-cli](https://www.npmjs.com/package/@playwright/cli):

```bash
npm run dev                                   # in another terminal
PW="npx -y @playwright/cli@latest"
$PW open "http://localhost:5173/?lng=de"      # ?lng=de|en forces a language
$PW resize 390 844                            # mobile
$PW screenshot --filename mobile.png --full-page
$PW click ".menu-toggle"                      # open the burger menu
$PW snapshot                                  # element refs for anything else to click
$PW resize 820 1180                           # tablet
$PW screenshot --filename tablet.png --full-page
$PW resize 1440 900                           # desktop
$PW screenshot --filename desktop.png --full-page
$PW set-reduced-motion reduce                 # page must still work and look calm
$PW console error                             # must be empty
$PW close
```

For each size check:

- **Layout:** no horizontal scrolling (the panorama scroller is the one intended exception) and no overlapping text or cut-off labels.
- **Interactive elements:** exercise every part you touched. That includes the burger menu, the "Add to calendar" dropdown (opens above other content, closes on outside click and Escape), the language switch, the photo dialog, anchor links under the sticky header, the pause button and hover or focus states.
- **Both languages** when copy changed. German strings are usually longer.

Screenshots are for checking, not for committing. `.playwright-cli/` is gitignored.

Before opening a PR also run `npm run type-check`, `npm run lint` and `npm run build`.
